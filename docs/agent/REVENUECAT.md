# CITYWALK RevenueCat

CITYWALK uses RevenueCat as the native purchase/subscription integration layer, while
PostgreSQL remains the authorization authority for protected CITYWALK access.

## Trust boundary

- RevenueCat `CustomerInfo`, Offerings and native purchase callbacks are client UX state.
- A client callback or local entitlement flag must never grant protected API/media access.
- Verified RevenueCat server webhooks reconcile provider lifecycle state into PostgreSQL.
- `commerce_entitlements` remains the record used by server authorization.
- Every RevenueCat delivery is idempotent by RevenueCat `event.id`.
- Subscription state is ordered by RevenueCat `event_timestamp_ms`; stale events are
  recorded but ignored instead of overwriting newer state.

## Mobile SDK keys

The React Native SDK uses RevenueCat **public SDK API keys only**:

- `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY`
- `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY`

Secret RevenueCat keys (`sk_...`) must never be placed in Expo public variables, native
bundles or GitHub. Production builds also reject RevenueCat Test Store `test_` keys.

## Webhook secrets

The server webhook endpoint is:

`POST /api/commerce/webhooks/revenuecat`

It requires both of these server-only environment variables:

- `COMMERCE_REVENUECAT_WEBHOOK_AUTHORIZATION` — exact Authorization header value
  configured on the RevenueCat webhook integration.
- `COMMERCE_REVENUECAT_WEBHOOK_SIGNING_SECRET` — HMAC signing secret generated by the
  RevenueCat webhook integration.

Neither variable is public and neither belongs in mobile/EAS public environment values.
No real secret is committed by MON-03.

Verification order:

1. compare the Authorization header using a constant-time comparison;
2. verify `X-RevenueCat-Webhook-Signature` against the **raw** request body using
   HMAC-SHA256 over `<timestamp>.<raw body>`;
3. reject signatures outside a five-minute replay tolerance;
4. only then parse JSON and touch PostgreSQL.

If either webhook secret is missing, the endpoint fails closed with 503. Invalid auth or
signatures fail before any commerce DB mutation.

## Identity

CITYWALK is guest-first. The mobile SDK can begin with a RevenueCat anonymous customer.
After Better Auth sign-in, the app calls `Purchases.logIn()` with the immutable Better
Auth `user.id`.

Webhook reconciliation accepts a non-anonymous CITYWALK user id from RevenueCat identity
fields and verifies that user still exists in PostgreSQL. Email, display name and other
mutable profile fields are never identities. If an account has been deleted, a later
webhook cannot recreate or reattach that account.

## Product contract

RevenueCat mobile packages:

- `$rc_monthly` → CITYWALK Premium Monthly
- `$rc_annual` → CITYWALK Premium Yearly
- `city_pass_72h` → Lübeck 72-hour City Pass

Store product identifiers:

- `com.citywalk.premium.monthly` → PostgreSQL product slug `citywalk-premium`
- `com.citywalk.premium.yearly` → PostgreSQL product slug `citywalk-premium`
- `com.citywalk.lubeck.pass72h` → PostgreSQL product slug
  `lubeck-digital-guide-pass-72h`

The PostgreSQL product + grant must exist before a webhook for that product can grant
anything. Unknown/unprovisioned product ids are recorded as ignored. This is deliberate:
the webhook never invents a paid product from untrusted payload data.

Premium products grant `feature:premium`. The Lübeck City Pass product grants
`city:lubeck` and its configured grant duration remains 72 hours.

The older sandbox-only direct Store contract remains isolated as
`com.citywalk.luebeck.premium` / `city:luebeck:premium` until the RevenueCat acceptance
work is complete. It is not the production RevenueCat product contract.

## Lifecycle reconciliation

Supported authoritative event behavior:

- `INITIAL_PURCHASE`, `RENEWAL`, `UNCANCELLATION`, `SUBSCRIPTION_EXTENDED`,
  `REFUND_REVERSED` → active subscription/access through the trusted period end.
- `NON_RENEWING_PURCHASE` → active, non-renewing access; a configured product grant may
  supply a finite server duration when the provider does not supply an expiration.
- `CANCELLATION` → stop renewal but keep already-paid access until expiration.
- `CANCELLATION` with `CUSTOMER_SUPPORT` → refund/revocation; revoke immediately.
- `BILLING_ISSUE` → record billing issue but do not treat it as expiration by itself.
- `SUBSCRIPTION_PAUSED` → record pause state; do not revoke before expiration.
- `EXPIRATION` → remove access.
- `PRODUCT_CHANGE` and unsupported event types are recorded as ignored until an
  authoritative purchase/renewal event confirms the effective product.

For recurring Premium products, a finite provider expiration is required before granting
or extending access. This avoids creating an accidental indefinite Premium entitlement.

## Offering and price presentation

The mobile Offering normalizer preserves RevenueCat/store `priceString`, currency and
numeric price. UI must display the localized store price. Product-planning values such as
€7.99 / €39.99 / €4.99 are target launch prices, not server purchase evidence.

## MON-04 City Pass flow

MON-04 reuses the existing City Unlock paywall/controller rather than creating a second
local access model.

RevenueCat City Pass UI is still opt-in behind:

`EXPO_PUBLIC_CITYWALK_REVENUECAT_CITY_PASS=1`

The flag is ignored while `EXPO_PUBLIC_CITYWALK_BILLING=sandbox`, so the direct native
sandbox verifier remains isolated for regression/acceptance work. No production profile
sets the RevenueCat City Pass flag in this PR.

When enabled:

1. the paywall loads the `city_pass_72h` package and displays its localized Store price;
2. a signed-in Better Auth user is synchronized to RevenueCat by immutable `user.id`;
3. an explicit Purchase action calls RevenueCat `purchasePackage()`;
4. an explicit Restore action calls RevenueCat `restorePurchases()`;
5. neither action grants CITYWALK access from `CustomerInfo`;
6. the UI waits for the verified RevenueCat webhook to reconcile PostgreSQL and polls the
   authenticated CITYWALK access endpoint for a short bounded period;
7. only a canonical server access response (`city_pass` or `premium`) unlocks the walk.

Ordinary Store cancellation maps to a benign cancelled state. If the webhook-backed
entitlement does not appear, the flow fails closed and the traveler can retry; there is
no local paid-access boolean.

## Deployment state

MON-01 through MON-03 are merged. MON-04 prepares the opt-in City Pass purchase/restore
path, but merging this code does **not** configure RevenueCat dashboard products, add real
SDK keys, set the feature flag in production, deploy production, run store acceptance or
enable live purchases. Those remain explicit release actions.
