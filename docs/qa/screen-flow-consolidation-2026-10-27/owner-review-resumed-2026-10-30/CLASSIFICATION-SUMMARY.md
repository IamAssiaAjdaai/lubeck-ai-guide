# Which overlaps are genuine duplicates?

No complete screen deletion is justified by the current evidence. The fourteen groups are not fourteen duplicate screens.

| Group | Actual overlap | Recommendation boundary |
|---|---|---|
| D01/D02 | Presentation variants in one Home/Account controller | Keep entry intents distinct; no second catalog/auth provider to merge. |
| D03 | Historically repeated per-draft interests question | Already resolved by approved S08; account defaults remain a different scope. Do not repeat that consolidation or add persistence. |
| D04/D05 | Reused time inputs and location service | Preserve different default/deadline/permission purposes; reuse contracts, not mandatory screens. |
| D06 | Genuine POI filtering/list/map responsibility overlap | Keep approved surfaces and dedicated Search; consider shared selectors only after owner defines state/reset ownership. Recent opened POIs are not saved search queries. |
| D07 | Same published routes in a summary and full collection | Legitimate summary/detail navigation. Decide collection entry, not catalog replacement. |
| D08/D09 | Similar preview/progress visuals over different domains | Keep personalized CurrentWalk and published editorial order/progress distinct. D09 and Screen14 stay deferred. |
| D10 | Place-grounded Guide vs unsupported-city fallback | Different capability/eligibility contracts; keep both honest. |
| D11 | Trips/Saved query modes of one screen | Legitimate execution/history vs bookmarks/replay. Preserve five tabs and storage scopes. |
| D12 | Web-specific/generic wrappers partially overlap | Preserve URL/editorial/audio/analytics contracts; Web-native platforms are not duplicates. No redirect/removal approved. |
| D13 | Root and next-preview already share LandingNext | Intentional UI reuse with different indexing/purpose; legacy preview needs owner-purpose decision, not automatic deletion. |
| D14 | One place URL changes mode with published context | Intent variant, not duplicate route. Existing Details opens ordinary S11; execution-return contract needs review with Screen14. |

Review order: D01/D02 for S03/S04 entry decisions; D03/D06 for scope and search/recommendations; D07 plus B-CONTENT-01 for S09/S12; D10/D11 for honest capability/task boundaries. Web D12/D13 can be reviewed independently. D08/D09/D14 require domain/Screen14 decisions before any convergence. This is review sequencing only, not implementation authorization.

POI categories (See/Eat/Fun), planner interests and dynamically available planner category filters are separate taxonomies/contracts. Reuse must not rename backend categories or silently discard controls.
